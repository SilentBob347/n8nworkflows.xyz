# Reply to WhatsApp sales leads with OpenAI, Supabase, and Slack alerts

### 1. Workflow Overview

This workflow implements an automated AI-driven sales assistant for WhatsApp using the Meta WhatsApp Cloud API, OpenAI, Supabase, and Slack. It processes inbound WhatsApp messages, prevents duplicate processing, manages customer CRM profiles and conversation logs, uses an AI agent grounded strictly in a local product catalog and business configuration to formulate responses, scores lead engagement levels, responds directly to customers on WhatsApp, and alerts the sales team on Slack for high-priority leads or human-escalation requests.

The logical execution blocks include:
- **1.1 Webhook Intake & Config:** Captures incoming webhooks (POST for messages, GET for Meta verification) and injects foundational client-specific business rules.
- **1.2 Normalize & Dedupe:** Extracts clean message attributes from raw Meta payloads and checks Supabase conversation logs to ignore duplicate requests.
- **1.3 Customer Lookup:** Inspects Supabase to identify existing customer records or provisions new ones, simultaneously gathering recent conversation history.
- **1.4 AI Sales Agent:** Pulls the active product catalog from Supabase and passes customer context, business facts, and chat history into an OpenAI-powered agent.
- **1.5 Score & Respond:** Evaluates lead temperature using rule-based scoring parameters and dispatches the synthesized reply back to the customer via WhatsApp.
- **1.6 Save & Notify:** Persists the conversation payload, updates CRM customer parameters, and evaluates whether to dispatch an operational alert to Slack.

### 2. Block-by-Block Analysis

---

#### Block 1.1: Webhook Intake & Config
**Overview:** This block establishes the inbound entry points for Meta’s WhatsApp Cloud API, handling both initial webhook subscription verification challenges and real-time message payloads, while supplying downstream nodes with localized business metadata.

**Nodes Involved:**
- `WhatsApp Verify Webhook`
- `Respond Verify Token`
- `WhatsApp Webhook`
- `Client Config`

**Node Details:**
- **WhatsApp Verify Webhook**
  - *Type and Technical Role:* `n8n-nodes-base.webhook` (GET method). Listens for Meta's verification challenge when registering the webhook URL.
  - *Configuration Choices:* Path set to `whatsapp-sales-agent`, response mode set to use a separate response node.
  - *Input/Output Connections:* Input: None (External Webhook); Output: `Respond Verify Token`.
  - *Edge Cases/Failure Types:* Verification token mismatch will result in authorization rejection.

- **Respond Verify Token**
  - *Type and Technical Role:* `n8n-nodes-base.respondToWebhook`. Validates the Meta verification token and responds with the challenge string or 'forbidden'.
  - *Configuration Choices:* Evaluates query parameter `hub.verify_token` against a hardcoded string ('REPLACE_VERIFY_TOKEN').
  - *Key Expressions:* `={{ $json.query['hub.verify_token'] === 'REPLACE_VERIFY_TOKEN' ? $json.query['hub.challenge'] : 'forbidden' }}`
  - *Input/Output Connections:* Input: `WhatsApp Verify Webhook`; Output: None.

- `WhatsApp Webhook`
  - *Type and Technical Role:* `n8n-nodes-base.webhook` (POST method). Receives production WhatsApp messages.
  - *Configuration Choices:* Path set to `whatsapp-sales-agent`. Automatically returns HTTP 200 immediately to prevent Meta retry loops.
  - *Input/Output Connections:* Input: None (External Webhook); Output: `Client Config`.

- **Client Config**
  - *Type and Technical Role:* `n8n-nodes-base.set`. Injects business configuration variables (business name, phone number ID, Slack channel ID, and operational facts like delivery, payment terms, and working hours).
  - *Configuration Choices:* Static JSON field assignments containing client parameters.
  - *Input/Output Connections:* Input: `WhatsApp Webhook`; Output: `Normalize WhatsApp Data`.

---

#### Block 1.2: Normalize & Dedupe
**Overview:** This block parses the nested Meta WhatsApp payload into a clean, flat data schema, filters out non-message status receipts, and queries Supabase to prevent duplicate processing of the same message ID.

**Nodes Involved:**
- `Normalize WhatsApp Data`
- `Check Duplicate Message`
- `Is New Message?`

**Node Details:**
- **Normalize WhatsApp Data**
  - *Type and Technical Role:* `n8n-nodes-base.code`. JavaScript code node that extracts user profile names, cleaned phone numbers, message texts, message IDs, and ISO timestamps.
  - *Configuration Choices:* Safely handles text messages, buttons, and interactive list replies, dropping read/delivery status callbacks.
  - *Input/Output Connections:* Input: `Client Config`; Output: `Check Duplicate Message`.
  - *Edge Cases/Failure Types:* Non-text payloads without explicit fallbacks can return empty strings; status callbacks return empty arrays to gracefully exit the flow.

- **Check Duplicate Message**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Database query node searching the `conversations` table for existing message IDs.
  - *Configuration Choices:* Table: `conversations`, Operation: `getAll`, Filter: `message_id` equals the normalized message ID, Limit: `1`, `alwaysOutputData: true`.
  - *Key Expressions:* `={{ $('Normalize WhatsApp Data').first().json.message_id }}`
  - *Input/Output Connections:* Input: `Normalize WhatsApp Data`; Output: `Is New Message?`.
  - *Edge Cases/Failure Types:* Supabase authentication failure or network timeout.

- **Is New Message?**
  - *Type and Technical Role:* `n8n-nodes-base.if`. Conditional routing gate.
  - *Configuration Choices:* Evaluates if the ID returned from the duplicate check is empty.
  - *Key Expressions:* `={{ $json.id }}` (Operator: empty)
  - *Input/Output Connections:* Input: `Check Duplicate Message`; Output: `Check Customer` (if true).

---

#### Block 1.3: Customer Lookup
**Overview:** This block looks up customer records in Supabase by phone number, pulls recent historical conversation context if the customer exists, or instantiates a new customer record if they are new.

**Nodes Involved:**
- `Check Customer`
- `Customer Exists?`
- `Get Customer History`
- `Create Customer`

**Node Details:**
- **Check Customer**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Queries the `customers` table matching the incoming phone number.
  - *Configuration Choices:* Table: `customers`, Operation: `getAll`, Filter: `phone` equals normalized phone, Limit: `1`, `alwaysOutputData: true`.
  - *Key Expressions:* `={{ $('Normalize WhatsApp Data').first().json.phone }}`
  - *Input/Output Connections:* Input: `Is New Message?`; Output: `Customer Exists?`.

- **Customer Exists?**
  - *Type and Technical Role:* `n8n-nodes-base.if`. Evaluates whether a customer record was found.
  - *Configuration Choices:* Checks if the customer table row ID is not empty.
  - *Key Expressions:* `={{ $json.id }}` (Operator: notEmpty)
  - *Input/Output Connections:* Input: `Check Customer`; Outputs: `Get Customer History` (True branch), `Create Customer` (False branch).

- **Get Customer History**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Retrieves past interaction logs from the `conversations` table.
  - *Configuration Choices:* Table: `conversations`, Operation: `getAll`, Filters: `phone` matches normalized phone, timestamp greater than or equal to 7 days ago. Limit: `20`, `alwaysOutputData: true`.
  - *Key Expressions:* `={{ $now.minus({ days: 7 }).toISO() }}`
  - *Input/Output Connections:* Input: `Customer Exists?` (True); Output: `Get Product Information`.

- **Create Customer**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Inserts a new row into the `customers` table for first-time interactions.
  - *Configuration Choices:* Table: `customers`, fields initialized with default status (`new`), lead score (`0`), and lead temperature (`Cold`).
  - *Key Expressions:* Uses normalized customer name, phone, and current ISO timestamp.
  - *Input/Output Connections:* Input: `Customer Exists?` (False); Output: `Get Product Information`.

---

#### Block 1.4: AI Sales Agent
**Overview:** This block loads the product catalog from Supabase, aggregates customer context and history, and passes everything to an OpenAI-backed agent configured with strict grounding system instructions.

**Nodes Involved:**
- `Get Product Information`
- `OpenAI Chat Model`
- `AI Sales Agent`

**Node Details:**
- **Get Product Information**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Fetches active product entries from the `products` table.
  - *Configuration Choices:* Table: `products`, Operation: `getAll`, Limit: `30`.
  - *Input/Output Connections:* Inputs: `Get Customer History` and `Create Customer`; Output: `AI Sales Agent`.

- **OpenAI Chat Model**
  - *Type and Technical Role:* `@n8n/n8n-nodes-langchain.lmChatOpenAi`. Language model provider integration.
  - *Configuration Choices:* Model: `gpt-4o-mini`, Temperature: `0.3`, Response Format: JSON object.
  - *Input/Output Connections:* Output: Linked to `AI Sales Agent` via `ai_languageModel`.

- **AI Sales Agent**
  - *Type and Technical Role:* `@n8n/n8n-nodes-langchain.agent`. LangChain advanced agent processing structured inputs and returning grounded JSON outputs.
  - *Configuration Choices:* System message enforces strict grounding rules (relying *only* on provided product data and client facts, keeping replies under 60 words, returning strict JSON containing `reply`, `intent`, `product_interest`, `buying_stage`, `is_interested`, and `needs_human`).
  - *Key Expressions:* JavaScript expression stringifying customer name, incoming message, sorted and sliced recent history, business metadata, and product array.
  - *Input/Output Connections:* Inputs: `Get Product Information` and `OpenAI Chat Model`; Output: `AI Lead Scoring`.
  - *Edge Cases/Failure Types:* JSON parsing errors if OpenAI fails to conform strictly to the schema (handled gracefully by downstream fallback scripts).

---

#### Block 1.5: Score & Respond
**Overview:** This block executes a rule-based scoring algorithm to compute lead temperature (Cold, Warm, Hot), constructs the response payload, and transmits the AI-generated message back to the user via the WhatsApp API.

**Nodes Involved:**
- `AI Lead Scoring`
- `Send WhatsApp Response`

**Node Details:**
- **AI Lead Scoring**
  - *Type and Technical Role:* `n8n-nodes-base.code`. JavaScript code node calculating numerical lead scores based on intents, keywords (e.g., demo, meeting, call), buying stages, and carries over historical engagement points.
  - *Configuration Choices:* Applies scoring cut-offs (Hot: >= 70, Warm: >= 40, Cold: < 40) and manages parsing fallbacks for malformed AI JSON outputs.
  - *Input/Output Connections:* Input: `AI Sales Agent`; Output: `Send WhatsApp Response`.

- **Send WhatsApp Response**
  - *Type and Technical Role:* `n8n-nodes-base.whatsApp`. Sends the outbound message payload via the Meta WhatsApp Cloud API.
  - *Configuration Choices:* Operation: `send`, Phone Number ID pulled from Client Config, Max Tries: `3`, Retry on failure enabled.
  - *Key Expressions:* `={{ $json.ai_response }}` (Text Body), `={{ $json.phone }}` (Recipient Phone Number).
  - *Input/Output Connections:* Input: `AI Lead Scoring`; Output: `Save Conversation`.
  - *Edge Cases/Failure Types:* Invalid phone formatting or expired Meta access tokens will trigger retries up to 3 times.

---

#### Block 1.6: Save & Notify
**Overview:** This block persists the conversation exchange in Supabase, updates the customer's CRM profile state, and conditionally dispatches a high-priority alert to a designated Slack channel if the lead is marked Hot or requires human intervention.

**Nodes Involved:**
- `Save Conversation`
- `Update CRM`
- `Hot Lead or Human Needed?`
- `Notify Sales Team`

**Node Details:**
- **Save Conversation**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Inserts a new record into the `conversations` table logging the interaction.
  - *Configuration Choices:* Table: `conversations`, maps customer ID, phone, message ID, customer message, AI response, intent, lead score, and timestamp.
  - *Input/Output Connections:* Input: `Send WhatsApp Response`; Output: `Update CRM`.

- **Update CRM**
  - *Type and Technical Role:* `n8n-nodes-base.supabase`. Updates the customer's profile row in the `customers` table.
  - *Configuration Choices:* Table: `customers`, Operation: `update`, matching on customer ID. Updates latest message, intent, product interest, score, temperature, buying stage, and updated timestamp.
  - *Input/Output Connections:* Input: `Save Conversation`; Output: `Hot Lead or Human Needed?`.

- **Hot Lead or Human Needed?**
  - *Type and Technical Role:* `n8n-nodes-base.if`. Conditional gate checking whether a sales alert should be raised.
  - *Configuration Choices:* Evaluates if lead temperature equals 'Hot' or `needs_human` is true.
  - *Key Expressions:* `={{ $('AI Lead Scoring').first().json.lead_temperature === 'Hot' || $('AI Lead Scoring').first().json.needs_human === true }}`
  - *Input/Output Connections:* Input: `Update CRM`; Output: `Notify Sales Team` (True branch).

- **Notify Sales Team**
  - *Type and Technical Role:* `n8n-nodes-base.slack`. Posts an operational notification message to Slack.
  - *Configuration Choices:* Authentication: OAuth2, Select: `channel`, Channel ID mapped dynamically from Client Config.
  - *Key Expressions:* Formatted Markdown message containing lead score, user details, product interest, customer message, and the bot's reply.
  - *Input/Output Connections:* Input: `Hot Lead or Human Needed?` (True); Output: None (Terminal node).
  - *Edge Cases/Failure Types:* Slack OAuth token revocation or missing channel permissions.

### 4. Reproducing the Workflow from Scratch

To rebuild this workflow manually in n8n, follow these sequential configuration steps:

1. **Create Webhook Entry Points:**
   - Add a **Webhook** node (`WhatsApp Verify Webhook`). Set HTTP Method to `GET`, path to `whatsapp-sales-agent`, and response mode to `Response Node`.
   - Add a **Respond to Webhook** node (`Respond Verify Token`). Configure response body expression to check `hub.verify_token` against your secure token string and output `hub.challenge`. Connect `WhatsApp Verify Webhook` output to `Respond Verify Token`.
   - Add a second **Webhook** node (`WhatsApp Webhook`). Set HTTP Method to `POST`, path to `whatsapp-sales-agent`.

2. **Configure Client Metadata:**
   - Create a **Set** node (`Client Config`). Connect `WhatsApp Webhook` output to it.
   - Add string string assignments for: `business_name`, `phone_number_id`, `slack_channel_id`, `delivery_areas`, `delivery_time`, `delivery_charges`, `payment_methods`, `return_policy`, `working_hours`, and `contact_phone`.

3. **Normalize and Deduplicate:**
   - Add a **Code** node (`Normalize WhatsApp Data`). Paste the extraction JavaScript snippet handling Meta WhatsApp Cloud API payloads and filtering out status receipts. Connect `Client Config` to it.
   - Add a **Supabase** node (`Check Duplicate Message`). Set Operation to `getAll`, table to `conversations`, add a filter where `message_id` equals `={{ $('Normalize WhatsApp Data').first().json.message_id }}`, limit to `1`, and enable `alwaysOutputData`. Connect `Normalize WhatsApp Data` to it.
   - Add an **If** node (`Is New Message?`). Set condition to check if `{{ $json.id }}` is empty. Connect `Check Duplicate Message` to it.

4. **Customer Lookup & Creation:**
   - Add a **Supabase** node (`Check Customer`). Set Operation to `getAll`, table to `customers`, filter where `phone` equals `={{ $('Normalize WhatsApp Data').first().json.phone }}`, limit to `1`, enable `alwaysOutputData`. Connect `Is New Message?` (True branch) to it.
   - Add an **If** node (`Customer Exists?`). Condition checks if `{{ $json.id }}` is not empty. Connect `Check Customer` to it.
   - From `Customer Exists?` True branch, add a **Supabase** node (`Get Customer History`). Set operation to `getAll`, table `conversations`, filter phone match and timestamp `>= {{ $now.minus({ days: 7 }).toISO() }}`, limit `20`, enable `alwaysOutputData`.
   - From `Customer Exists?` False branch, add a **Supabase** node (`Create Customer`). Set operation to `insert`, table `customers`, setting initial lead score to `0`, temperature to `Cold`, and source to `whatsapp`.

5. **AI Sales Agent Setup:**
   - Add a **Supabase** node (`Get Product Information`). Set operation to `getAll`, table `products`, limit `30`. Connect outputs from both `Get Customer History` and `Create Customer` into this node.
   - Add an **OpenAI Chat Model** sub-node, configure model as `gpt-4o-mini`, temperature `0.3`, response format `json_object`, and link an active OpenAI credential.
   - Add an **Advanced AI Agent** node (`AI Sales Agent`). Set prompt type to define, pass the customer details, stringified history, business info object, and product list into the prompt. Link the `OpenAI Chat Model` to its `ai_languageModel` input. Connect `Get Product Information` to its main input.

6. **Lead Scoring & WhatsApp Dispatch:**
   - Add a **Code** node (`AI Lead Scoring`). Implement rule-based scoring logic parsing the AI JSON output, calculating thresholds, and preparing the response structure. Connect `AI Sales Agent` to it.
   - Add a **WhatsApp** node (`Send WhatsApp Response`). Set operation to `send`, credential to Meta WhatsApp, recipient phone `={{ $json.phone }}`, text body `={{ $json.ai_response }}`, phone number ID `={{ $('Client Config').first().json.phone_number_id }}`, retry on fail enabled. Connect `AI Lead Scoring` to it.

7. **CRM Logging & Slack Notifications:**
   - Add a **Supabase** node (`Save Conversation`). Insert a row into `conversations` mapping customer ID, phone, message ID, messages, AI response, intent, and lead score. Connect `Send WhatsApp Response` to it.
   - Add a **Supabase** node (`Update CRM`). Set operation to `update`, table `customers`, filter ID equals customer ID, updating latest message, intent, product interest, score, temperature, and updated timestamp. Connect `Save Conversation` to it.
   - Add an **If** node (`Hot Lead or Human Needed?`). Condition checks if `lead_temperature === 'Hot' || needs_human === true`. Connect `Update CRM` to it.
   - Add a **Slack** node (`Notify Sales Team`). Connect to the True branch of the If node. Set authentication to OAuth2, select channel by ID `={{ $('Client Config').first().json.slack_channel_id }}`, and configure formatted notification text.
